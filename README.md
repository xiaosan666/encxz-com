# 英语听力教学视频生成器

读取 `data/en.xlsx` 的每一行数据 + `data/*.mp3` 音频，生成 1920×1080 / 30fps 的
「两遍播放」教学视频：

```
封面(2s) → 第一遍逐句翻页 → 静止 2s → 第二遍滚动歌词 → 片尾
```

- **第一遍**：每页一句英文（居中大字）+ 一句中文（底部小字），随音频推进翻页，右下角有页码。
- **第二遍**：整篇英文以滚动歌词形式呈现，当前句跟随音频高亮（放大 + 变酒红加粗），
  未播到的句子为灰色，列表自动滚动。
- **模版固定**：左上角 logo「英语初学者 / encxz.com」，右上角语言等级（A1/A2/B1/B2），
  两遍都在页眉中间显示本行英文标题。

---

## 1. 数据格式

`data/en.xlsx` 第 1 个工作表，第 1 行是表头，从第 2 行开始是数据：

| 列 | 含义 | 是否必需 |
|---|---|---|
| A | Level：`A1` / `A2` / `B1` / `B2` | 是（显示在右上角） |
| B | Title 英文标题 | 是（封面 + 页眉标题） |
| C | script 英文文稿（可用换行分段） | 是 |
| D | mp3 文件名 | 是（用于在 `data/` 里找音频） |
| E | Title 中文标题 | 封面用，可空 |
| F | script 中文译稿 | 第一遍中文字幕用，可空 |

音频放在 `data/` 下即可；脚本会先按文件名精确匹配，其次按归一化名称、
最后按 `A1-001` 这样的编号前缀匹配，所以大小写、`_`/`-` 差异都能容忍。

## 4. 字幕同步（核心）

### 默认方案：ASR 词级对齐

```
快 → 准 → 稳
```

1. **faster-whisper 转写**音频，得到每个词的 `(词, 开始, 结束)`（int8 / CPU，约 **4 秒/条**）；
2. 把脚本和转写结果都切成小写词元，用 `difflib` 求最长匹配块；
3. 每个脚本词元取它匹配到的转写词元的时间，未匹配的用前后线性插值；
4. 每句起点 = 该句第一个词元的时间，终点 = 下一句的起点。

> ⚠ **时间轴的 `duration` 必须取音频文件的真实长度（ffprobe），不能用最后一个词的结束时间。**
> 录音结尾普遍带 1~3 秒静音，如果按最后一个词算，时间轴会比音频短一截，结果是：
> 第二遍的整体起点提前（字幕快于语音）、而且 `-shortest` 会把第二遍的结尾剪掉
> （表现为"视频提前结束、音频没播完"）。`load_or_align` 每次加载缓存都会拿
> `probe_duration()` 复核一遍 `duration`，旧缓存会自动校正（只改 duration，不动句子时间）。

输出里的 **`与脚本词匹配率`** 就是质量指标：≥95% 说明识别结果与文稿对得上，
时间可信；偏低会告警，可用更大的模型重跑：

```bash
.venv/bin/python make_video.py --rows 2 --asr-model medium --realign
```

### 备选方案：静音检测 + 动态规划

`--align-engine silence`：用 `ffmpeg silencedetect` 找停顿，按词数估算期望切点，
再用动态规划挑一组最接近期望的切点。**不需要任何模型**，但实测误差可达 2–4.5 秒
（停顿只能说明"这里换气"，不能说明"这句话在第几秒"），只建议在无法使用 ASR 时兜底。

### 诊断工具

```bash
# 逐句对比两种方案，看差在哪里
.venv/bin/python tools/asr_check.py --rows 2

# 换更大模型核对
.venv/bin/python tools/asr_check.py --rows 2 --model medium --show-text

# 校验「时间轴 / 成品视频」与「音频」是否真的对齐（含抽帧实测切换时刻）
.venv/bin/python tools/verify_sync.py --rows 2-4
.venv/bin/python tools/verify_sync.py --level A1 --probes 1
```

`tools/verify_sync.py` 会逐项核对：第二遍起点、成品总长、结尾被切掉多少语音、
成品音轨里第二遍音频的真实位置（互相关），并**二分找出成品画面真正切换的时刻**
与人声起点比较（第一遍翻页 / 第二遍字幕各测几处）。全部行通过才算对齐。

### 人工微调

- **时间轴**：编辑 `cache/<行>-<音频名>.<引擎>.timings.json`，改 `sentences[].start/end`，
  并把 `locked` 设为 `true`，之后重新运行会原样沿用。
- **逐句英中对照**：`--export-lines` 生成 `cache/rowN.lines.json`，改完自动生效，删除即回到自动对齐。

## 6. 英中断句与句级对齐

### 先做换行归一化

原始文稿里有 27 行的换行是**断在句子中间**的（例如 `... but I love` / `that song.`，
来自源文件的硬换行）。如果直接按换行分段，视频里就会出现只写着 "but I love" 的一页。
所以脚本在分段前会先合并这类断行：

> 只有当"上一段没有以句末标点结束"时才合并，因此正常的段落划分不受影响。
> 英文与中文用同一套规则，**表格文件本身不会被修改**。

### 再逐层对齐

1. **段落级对齐**：允许英中段落数不一致（译文常把两段并成一段、或把一段拆成两段），
   用动态规划求出段落的一一映射；
2. **句级对齐**：在每个段落组内，英文按 `[.!?]` 断句（带缩写保护，
   `Mr.` / `U.S.` / 首字母缩写不会误切），中文按 `。！？` 断句；
   句数相等时直接 1:1，句数不等时才用 DP 决定在哪合并或拆分；
3. **多句共用一句中文时**：优先按逗号/顿号把中文切成与英文句数相同的份数；
   如果切出来有太短的碎片（<4 字），就整句重复显示，避免把中文切得不成句；
4. **兜底**：任何一页中文为空时，沿用最近的非空中文，保证每页都有中文字幕。

实测 198 行 / 2438 页：中文为空 0 页，与上一页中文重复的仅 64 页（2.6%）。

## 9. 常见问题

**Q：第二遍字幕比语音快 / 视频比音频先结束？**
这是同一个根因的两面：时间轴的 `duration` 不是音频真实长度。跑一下
`.venv/bin/python tools/verify_sync.py --rows <行号>`，它会直接把偏差量出来
（第二遍起点差多少秒、结尾切掉多少秒语音、画面实测比人声早多少秒）。
如果确认偏了，删掉该行的缓存重新对齐即可（`--realign`）；正常加载缓存时也会自动校正 `duration`。

**Q：某一行的视频声音明显比别的行小（或大）？**
源 mp3 的响度差异很大（全量实测 **-46.1 ~ -9.0 LUFS**，中位数 -22.5），而编码时若不做补偿，
视频就会原样继承源的音量。现在 `video_gen/encode.py` 的 `build_audio()` 会自动补一道
**静态增益归一化**：先量源音频的 EBU R128 响度，再施加「目标响度 − 实测响度」的线性增益，
把每一行都对齐到 `config.AUDIO_TARGET_LUFS`（默认 **-21.5 LUFS**，即现有 A1 视频的响度中心）。

几个要点：

- 增益是**纯线性**的，不做动态压缩、不做限幅，**音频时长一个采样都不变**，
  所以逐句时间轴和已人工校对的缓存不受影响（重新生成只会变响，不会跑偏）；
- 加在**语音段**上而不是拼接后的整轨上，静音留白不参与测量、也不会被放大；两遍用同一个增益，
  不会出现第一遍和第二遍音量不一致；
- 增益会把真峰值推过 `AUDIO_TRUE_PEAK_DBTP`（默认 -1.5 dBTP）时，**以峰值上限为准**：
  宁可响度略低于目标也不削波，此时逐行报告里会注明「已按峰值上限收窄」；
- 想整体调整音量改 `AUDIO_TARGET_LUFS` 即可（例如想更响可用广播/播客常用的 `-16`）；
  想恢复改动前的行为，把 `AUDIO_NORMALIZE` 设成 `False`。

每行渲染完会回显实际施加的增益，形如
`音量归一化：-30.5 → -21.5 LUFS（增益 +9.2 dB，峰值 -9.5 → -0.3 dBTP）`。

> 测量是在**转成 44.1kHz 单声道之后**的信号上做的，和真正施加增益的那一路完全一致。
> 这一点必须如此：立体声降单声道时响度基本不变，但真峰值最多会抬高约 3 dB，
> 若用立体声的测量值给单声道信号定增益，峰值上限会少算约 3 dB，安静的音源会被推成削波。

**Q：改了 en.xlsx 的文稿或译文，要手动清缓存吗？**
不用。时间轴缓存里存了句表指纹，文稿/译文一变，指纹就对不上，脚本会自动重新对齐。
换 `--align-engine` 也会各存一份缓存，互不覆盖。

**Q：只想改某一句话的时间，不想重跑 ASR？**
编辑对应的 `cache/<行>-<音频名>.asr.timings.json`，改 `sentences[].start/end`，
把 `locked` 设为 `true` 即可。之后即使文稿没变也会原样沿用。

**Q：某一行 ASR 的匹配率很低怎么办？**
先确认这一行的音频是不是拿错了（与 D 列文件名是否对应）。
如果音频没问题，用更大的模型重跑：`--asr-model medium --realign`。

**Q：批量跑很慢 / 内存吃紧？**
渲染约 20 秒/条（80 秒音频），ASR 约 4 秒/条。`--jobs N` 会开 N 个进程，
**每个进程各加载一份 whisper 模型**（small 约 1GB 内存），建议 `--jobs 2~3`。
也可以先 `--align-only` 把时间轴全部算好，再 `--jobs 4` 只渲染。

**Q：想换背景底图 / 改配色？**
改 `video_gen/config.py` 里的颜色与几何常量，然后 `--rebuild-template` 重建底图。
模版几何数值是从示例视频逐帧量测出来的，改之前建议先看第 5 节的对照表。

**Q：第一遍没有中文字幕？**
说明该行 F 列（`script 中文`）为空。按第 8 节补充译文即可。

## 8. 已知限制

- ASR 对齐依赖脚本与音频内容一致。实测第 2–6 行匹配率 99–100%；
  若某行文稿与录音有出入，匹配率会下降并告警，此时可改用 `--export-lines` 人工核对文稿。
- 口音极重或录音质量差时 small 模型可能识别不准，换 `medium` 通常能解决；
  仍不行则用 `--align-engine silence` 或人工微调时间轴。
- 英中句级对齐是规则 + 动态规划，个别句子可能需要用 `--export-lines` 人工修订。
- 背景底纹是程序生成的近似质感，配色与几何已对齐，但非像素级一致。
